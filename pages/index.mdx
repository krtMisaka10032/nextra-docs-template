# nl2sql-proxy 使用手册

**一个入口，查所有库。** nl2sql-proxy 是 PostgreSQL 的统一查询代理：外部系统不再直连数据库，而是向本服务提交**自然语言问题**或 **SQL**，统一拿到查询结果、最终执行的 SQL 与审计记录。

## 它解决什么问题

- 数据分散在多个 PostgreSQL 库和视图里，业务方与 Agent 各自维护连接、查询脚本
- 自然语言问数需要稳定的表结构筛选、业务口径与失败重试
- 直接发放数据库账号风险大，缺少统一的安全门禁和操作审计

## 核心能力

| 能力 | 说明 |
| --- | --- |
| 双模式查询 | `mode=nl` 自然语言问数，`mode=sql` 直接执行 SQL，`auto` 自动识别 |
| 多数据源 | 在配置文件中声明多个 PostgreSQL 数据源，按 `datasource` 路由 |
| 安全策略 | 单语句限制、只读复检、函数黑名单、无 WHERE 写拒绝、写操作二次确认 |
| SQL 改写 | 无 LIMIT 的 SELECT 自动注入 LIMIT；写操作自动追加 `RETURNING *` |
| NL2SQL | qoder CLI 生成 → 静态校验 → 执行 → 数据库报错回传修复（最多 2 轮） |
| Schema 自助 | `/v1/schema` 接口与 MCP 工具，内省结果缓存 10 分钟 |
| 双协议接入 | HTTP JSON API 与 MCP（streamable-http），Agent 一次工具调用即可查库 |
| 审计日志 | 每次请求落 SQLite：谁、何时、输入、最终 SQL、行数、耗时、错误码 |

## 三十秒体验

假设服务已在 `127.0.0.1:8731` 启动，API Key 为 `YOUR_KEY`：

```bash
API=http://127.0.0.1:8731

# 1. 健康检查（无需鉴权）
curl -s $API/healthz

# 2. 自然语言问数
curl -s -X POST $API/v1/query \
  -H 'X-API-Key: YOUR_KEY' -H 'Content-Type: application/json' \
  -d '{"input":"最近7天每天的销量","mode":"nl","datasource":"sales"}'

# 3. 直接执行 SQL，返回 markdown 表格
curl -s -X POST $API/v1/query \
  -H 'X-API-Key: YOUR_KEY' -H 'Content-Type: application/json' \
  -d '{"input":"SELECT * FROM orders","mode":"sql","output":"markdown","max_rows":5}'
```

## 架构一览

```text
Client ── HTTP POST /v1/query ──► FastAPI ─┐
Client ── MCP streamable-http /mcp ────────┤
                                           ▼
                                      QueryEngine
   ┌──────────┬───────────┬────────────┬────────────┬──────────┐
   ▼          ▼           ▼            ▼            ▼          ▼
 PoolRegistry SQLPolicy  SchemaCache  NL2SQL      Formatter  AuditLog
 (asyncpg×N) (sqlglot)   (pg_catalog) (qoder CLI) (md/json)  (SQLite)
```

> **设计前提**：服务按**单进程**设计（连接池、缓存、审计、LLM 并发信号量都在进程内），部署时只启动一个 worker。
