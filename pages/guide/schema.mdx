# Schema 缓存与自助

服务会从 PostgreSQL 系统目录内省表结构，供 NL2SQL 提示词和 schema 查询接口使用。你不需要手动维护建表信息。

## 内省内容

对每个数据源，读取除 `pg_catalog`、`information_schema` 之外的模式，对象类型包括：

- 普通表（`r`）
- 分区表（`p`）
- 视图（`v`）

每张表包含：

- 表名、schema、表注释
- 行数估算（来自 `reltuples`，可能不是精确值）
- 列名、类型、是否可空、默认值、列注释
- 主键标记
- 外键（列 → 引用表.列）

## 缓存策略

| 行为 | 说明 |
| --- | --- |
| TTL | 600 秒（10 分钟） |
| 启动预热 | 启动时尝试刷新默认数据源；失败不阻塞启动 |
| 自动过期 | 超过 TTL 后下一次读取会自动刷新 |
| 手动强刷 | `GET /v1/schema?refresh=1` |
| 缓存范围 | 每个数据源一份，进程内内存 |

> 数据库发生 DDL 后，建议调用 `refresh=1`。重启服务也会重新内省。

## HTTP 接口

### 列出所有表

```bash
curl -s "$API/v1/schema?datasource=datav" -H "X-API-Key: $KEY"
```

```json
{
  "datasource": "datav",
  "table_count": 2,
  "tables": [
    {
      "schema": "public",
      "name": "blind_box_rate",
      "comment": "盲盒概率配置",
      "est_rows": 120,
      "column_count": 6
    },
    {
      "schema": "public",
      "name": "v_xindong_base_daily",
      "comment": "按日基础汇总",
      "est_rows": 365,
      "column_count": 12
    }
  ]
}
```

| 查询参数 | 默认值 | 说明 |
| --- | --- | --- |
| `datasource` | 第一个数据源 | 数据源名称 |
| `refresh` | `0` | 设为 `1` 强制刷新缓存 |

### 查看单表详情

```bash
curl -s "$API/v1/schema/blind_box_rate?datasource=datav" \
  -H "X-API-Key: $KEY"
```

```json
{
  "datasource": "datav",
  "schema": "public",
  "name": "blind_box_rate",
  "comment": "盲盒概率配置",
  "est_rows": 120,
  "column_count": 6,
  "columns": [
    {
      "name": "id",
      "type": "integer",
      "nullable": false,
      "default": "nextval('blind_box_rate_id_seq'::regclass)",
      "comment": null,
      "is_pk": true
    }
  ],
  "foreign_keys": [
    {"column": "sku_id", "ref_table": "blind_box_sku", "ref_column": "id"}
  ]
}
```

表名支持两种写法：`table` 或 `schema.table`。表不存在返回 HTTP 404。

## 描述覆盖

`schema_overrides` 会修改内省结果里的表/列描述，追加在数据库注释之后：

```yaml
schema_overrides:
  datav:
    tables:
      gifts:
        desc: "礼物流水底表（700万行级），分析优先用各 v_* 汇总视图"
```

这段描述会同时出现在：

- NL2SQL 的表结构提示词中
- `/v1/schema`、`/v1/schema/{table}` 的 `comment` 字段中

## 常见问题

**表结构变了但接口没更新？**

调用 `refresh=1`，或等待 TTL 过期，或重启服务。

**行数估算不准？**

`reltuples` 是 PostgreSQL 的统计估算，不会实时更新。它只用于给模型提供规模参考，不参与结果计算。

**看不到某张表？**

检查 schema 是否在 `pg_catalog` / `information_schema` 之外，以及对象类型是否为普通表、分区表或视图（物化视图、外部表不在内省范围）。
